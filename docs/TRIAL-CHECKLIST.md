# 双人试用清单（10 分钟）· v2

> 目标：两个人在 10 分钟内**独立**跑完，判断这个工具"能不能用"，并留下可复现的失败记录。
> 角色：**甲 = 复现者**（按计划办事的人），**乙 = 挑错者**（专门找"它在骗我"的地方）。
> 分工：甲操作，乙只记录与挑错；**乙不要帮甲点鼠标**，也不要在甲操作时给提示。

## ⚠️ 两条通道，结果分别记录，不能互相替代

| 通道 | 需要模型密钥 | 覆盖范围 | 记录表 |
| --- | --- | --- | --- |
| **通道 1 · 示例体验** | **不需要** | 示例项目（3 篇虚构论文）、方法对比、实验检查、**生成验证计划**、状态操作、导出 Markdown、引用/规则标签的展示 | 表 A |
| **通道 2 · 真实验收** | **需要**（见第 0 节） | 上传**真实 PDF** → 抽取字段与证据 → 复现缺项 → 问答 | 表 B |

**硬规则：通道 1 通过 ≠ 通道 2 通过。** 示例数据是内置的，它不验证"能不能真的读一篇 PDF"。
没有密钥时：**只在表 A 记录，表 B 一律写「未测」**，不得据此宣布通过。

---

## 0. 环境准备（1 分钟）

1. 甲在项目目录启动本地服务（二选一）：
   - 有密钥：把 `.env.local.example` 另存为 `.env.local` 并填好，然后
     `powershell -ExecutionPolicy Bypass -File scripts\start-local.ps1`
   - 没密钥：直接 `node server/index.mjs`（示例体验够用；真实抽取/问答会返回 503）
2. 浏览器打开 **http://127.0.0.1:8787/**，看到首页即服务正常。
3. **乙先验证"模型到底通不通"**（这一步不能省，也不能只看 hasCredentials）：
   - 浏览器打开 http://127.0.0.1:8787/api/health → 记下 `hasCredentials` 与
     `capabilities.realLlmExtract / realLlmQa`；
   - 再执行 `node scripts/probe-minimal-llm.mjs` → **只有它显示 ✅ 才算模型可用**。
   - 若显示 ❌（例如 `503 NO_CREDENTIALS`）→ 在表 B 第一行记「模型不可用」，**通道 2 直接判未测**，
     并跳到通道 1。

## 通道 1 · 示例体验（不需要密钥）

### 1.1 甲：载入示例并看引用（2 分钟）

1. 首页点「载入示例项目」。
2. 进入「论文库」→ 打开任意演示论文 → 任意字段点「🔍 查看依据」→ 看弹出的英文原文片段与页码。
3. 进入「方法对比」→ 切换「对比口径」下拉，看同一项判定的变化与「x/y 篇包含」。

**乙检查**：界面**每一处**是否都标注了「演示数据，非真实论文分析」？有没有把示例数据说得像真实分析？缺标 → ❌。

### 1.2 甲：看它发现了什么（2 分钟）

1. 「实验检查」→ 看「需确认的条件」与「复现缺项」。
2. 找一条「未找到」，再找一条「未检查」（如果有）；切换口径再看一遍。
3. 看页面上是否展示检查规则版本号与规则编号（R-0x）。

**乙检查（挑错点）**：
- 判定「信息不足」时理由有没有说清**缺什么、哪一篇没写**？
- 「未找到」和「未检查」有没有分开？说「未找到」但同一页提示有页面未处理 → ❌。
- 有没有出现"论文有错误 / 方法更好 / 排名"？出现即 ❌（产品红线）。

### 1.3 甲：生成验证计划 + 试状态门禁（4 分钟）

1. 「实验检查」右上角点「🧭 生成验证计划」→ **先不动任何默认值**直接生成。
2. 再点「示例 A：仅 CPU、时间有限」→ 与上一步输出对比（任务数量、有没有训练步骤、规模说明）。
3. 挑一个实验：勾 2~3 个步骤 → **不填实际结果**，直接点状态里的「已完成」。
4. 只填「我的观察」，再试一次「已完成」。
5. 把「实际结果」填上（随便写 `MSE=0.4`）→ 状态应变成「已完成」，且**没有**"假设成立/验证成功"字样。
6. 点「导出 Markdown」，打开文件看参数来源、规则编号、状态与提示语。

**乙检查（挑错点）**：
- 参数来源三类标签齐不齐（论文给出的设置 / 工具建议的设置 / 待确认）？
- 论文没写清楚的项（学习率、批大小、种子等）有没有被**编造出具体数值**？出现即 ❌。
- 规模说明里有没有"几分钟跑完""显存够用"？出现即 ❌。
- 步骤 3 与 4：**「已完成」能不能点成功？** 成功 = ❌（本轮修的状态门禁）。
- 步骤 3/4 被拦下时，界面有没有说明**为什么**？（有解释 ✅ / 静默无响应 ❌）
- 导出的 Markdown 状态与页面一致吗？（观察非空但无实际结果 → 必须是「待确认」）
- 计划里的实验数量会不会**只有 1 个**？如果只有 1 个，且理由写清了"资源或数据不支持更多" → ✅（这是允许的，不算缺陷）

## 通道 2 · 真实验收（需要模型可用）

### 2.1 甲：上传真实 PDF（3 分钟）

1. 「论文库」→ 上传**两篇**时间序列预测论文（文本型 PDF）。
2. 等状态到「字段已抽取」。
3. 打开任意一篇 → 任意字段「🔍 查看依据」。

**乙检查**：把侧栏英文原句复制到 PDF 里搜 —— **搜得到吗？页码对吗？** 搜不到/页码错 → ❌（截图字段名）。

### 2.2 甲：真实问答（3 分钟）——题目已按原文核对，不要改问法

> 这两题是**先核对过原文**才选的：**两篇论文都没有报告训练总时长**；
> 而 Autoformer **明确写了**「单块 NVIDIA TITAN RTX 24GB」（实现细节，第 7 页）。
> 所以一问"没写的"、一问"写了的"，正好检验它是真读了还是顺着问题编。

**第 1 问（应拒答）**：「这两篇论文的训练总时长是多少？总共用了多少 GPU 小时？」
- ✅ 期望：明确说**没有找到 / 无法确定**，并（最好）指出论文只给了早停轮数等设置。
- ❌ 若给出"训练了 X 小时/X 天"这类具体数字 → 记 ❌（这是幻觉）。

**第 2 问（应回答）**：「Autoformer 的实验用了几块 GPU？型号是什么？」
- ✅ 期望：**1 块 / 单块 NVIDIA TITAN RTX 24GB**，并给出页码。
- ❌ 说"论文没有写" → 记 ❌（这说明它没读到第 7 页，或链路有问题）。

**第 3 问（分界）**：「DLinear 的实验用了几块 GPU？」
- ✅ 期望：说**没有明确报告数量**（原文只在有效性分析里提到 Titan XP）。
- ❌ 直接答"1 块"却给不出页码 → 记 ❌（把另一篇的事实串过来了）。

**乙检查（每条结论都要看标签）**：
- 标签属于哪一类：原文支持 / 部分支持 / 系统事实 / **规则推导** / **建议·待验证** / 未复核？
- 点开「规则推导」：有没有**规则编号 + 输入字段 + 结果**？
- 有没有"程序判信息不足、它却说条件一致/差异"却仍标「规则推导」？出现即 ❌。
- 撤回区里的结论是不是**论文事实类**？（系统事实与规则推导不应出现在撤回里）

### 2.3 乙：边界检查（1 分钟）

1. 上传一个 `.txt` 文件 → 应提示格式不支持。
2. 再上传同一个 PDF → 应提示重复。
3. 停掉后端（Ctrl+C）后提问 → 应明确显示"未连接模型"，而不是给固定答案。

## 通过标准

**通道 1（示例体验）通过**需同时满足：
1. 表 A 的**三行状态门禁全 ✅**（只勾步骤 / 只填观察 / 填了实际结果）；
2. 表 A **没有任何**编造数值、耗时或显存承诺、越界排名的 ❌；
3. 演示数据处处标注。

**通道 2（真实验收）通过**需同时满足：
1. 模型可用性自检 ✅（只看 `hasCredentials=true` 不算）；
2. 引用能搜到且页码正确；
3. 第 1 问拒答、第 2 问答对、第 3 问说"没写"—— **三问全对**；
4. 表 B 无 ❌。

**只要通道 1 的状态门禁有 ❌，或通道 2 的三问有一问错，就判该通道不通过并停在这里。**
两通道分别给结论；**通道 1 通过不能写成"整体通过"**。

## 出问题时的最小信息包（便于定位）

1. 哪一步、点了什么按钮；2. 浏览器与系统版本；3. 截图（含页面与状态标签）；
4. 若连了后端：终端最后 20 行（**注意去掉密钥**）；5. 期望看到什么 / 实际看到什么。

> 复现命令：`npm run build` → `node server/index.mjs` → http://127.0.0.1:8787/ ；
> 自动化回归：`npm run test:logic`（103 项）、`npm run test:verify`（13 项）、`npm run test:e2e`（需密钥）。
